# LA2028 Database

База данных проекта LA2028 — статистика результатов по всем дисциплинам до Олимпиады 2028 (LA2028), на основе которой в дальнейшем строятся предикты на будущие результаты.

## Описание проекта

Проект предоставляет:
- **SQL схему** PostgreSQL (схема `core`) для спортивной аналитики
- **Систему миграций** на базе Liquibase для версионирования изменений схемы
- **Docker-контейнеры** для быстрого разворачивания тестовой среды

## Модель данных

Схема `core` содержит следующие таблицы:

| Таблица | Назначение |
|---------|------------|
| `tournaments_types` | Типы турниров со степенью важности (0 — ОИ, 1 — ЧМ, 2 — континентальные) |
| `regions` | Регионы мира |
| `region_tournaments_types` | Связь региона и типов турниров, проводимых в этом регионе |
| `countries` | Страны с IOC-кодами |
| `sports` | Виды спорта |
| `disciplines` | Дисциплины, привязанные к виду спорта |
| `athletes` | Спортсмены (страна, вид спорта, дата рождения, wiki-ссылка) |
| `athlete_disciplines` | Связь спортсмена и дисциплин участия |
| `tournaments` | Турниры (вид спорта, тип, регион, общие даты) |
| `tournament_disciplines` | Дисциплины-сессии турнира с собственными датами |
| `results` | Результаты выступлений (место, счёт) |

### Особенность модели турниров

Один турнир может охватывать несколько дисциплин, которые проходят в разные даты.
Например, волейбол на Олимпийских играх имеет 2 дисциплины (мужчины и женщины),
игра которых не совпадает по времени. Для этого вводится сущность
`tournament_disciplines`: для одного турнира (строка в `tournaments`) создаётся
отдельная запись на каждую участвующую дисциплину со своими `start_date`/`end_date`.
Результаты привязываются к такой паре турнир-дисциплина.

## Запуск базы данных

Проект поддерживает два режима инициализации БД:

#### 1. Режим миграций (рекомендуется по умолчанию)
Использует Liquibase для последовательного применения миграций:
```bash
make up
# или явно
make up-migrations
```

#### 2. Режим DDL скриптов
Применяет схему напрямую из SQL файлов:
```bash
make up-schema
```

### Управление контейнерами

- **Остановить БД:** `make down`
- **Остановить и удалить тома (очистить данные):** `make down-volumes`
- **Просмотреть логи:** `make logs`
- **Просмотреть все доступные команды:** `make help`

### Подключение к базе данных

| Параметр | Значение |

## Миграции

⚠️ **Важно:** После каждого изменения схемы необходимо сгенерировать миграцию.
Подробная документация по работе с миграциями находится в [MIGRATIONS.md](MIGRATIONS.md).

Основные команды:
```bash
# Применение всех миграций
./scripts/migrate.sh update --url localhost:5432 --db postgres

# Создание миграции (diff между рабочей бд и preprod)
./scripts/migrate.sh make-migration --url localhost:5432 --db preprod --ref-url localhost:5432 --ref-db postgres --script my_migration.sql

# Откат миграций до тега
./scripts/migrate.sh rollback --url localhost:5432 --db postgres --tag 20261116_000000_baseline.sql
```
